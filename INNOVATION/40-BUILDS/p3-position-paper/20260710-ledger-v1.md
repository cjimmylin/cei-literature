### 1.3 Exactly where the drift comes from (three independent causes)

1. **Raw occurrences vs. distinct sources (the "47 / 23" figure).** The prose/screening "47 ⚠ /
   23 SEARCH-CONFIRMED" is a count of raw tag *occurrences* across the whole document. Whole-document
   raw `[⚠ …]` closed-tag occurrences = **47** (verified by grep), which sweeps in all 42 ledger-⚠
   table rows plus inline prose tags plus the DRAFT-banner's illustrative `[⚠]` / `[SEARCH-CONFIRMED]`
   mentions (front-matter lines 19–20). These are not distinct sources. The ledger enumerates distinct
   sources and is authoritative per FC-15.

2. **One source cited twice in prose (`arXiv:2601.20299`).** The peer-prediction paper is tagged
   **twice** in the body — §4 line 178 as `[⚠ arXiv:2601.20299, ICLR 2026]` (oversight / G-07) and
   again §4.1 line 206 as `[⚠ arXiv:2601.20299]` (judge-collapse baseline / G-09). It is correctly a
   **single ledger row** (row W10 below), which the draft states in its own totals note (v0 lines
   512–514). This double-cite inflates any raw-occurrence tally by 1 but must not inflate the distinct
   count.

3. **The draft's own ⚠ total is off by one (41 vs. 42).** The v0 "Ledger totals" line reports **41**
   ⚠, but the ⚠ table actually contains **42** data rows (verified: 42 distinct prose ⚠ arXiv IDs =
   42 ledger ⚠ rows, a perfect set match; no duplicate IDs within the table). The most likely cause of
   the hand-count slip: the EVALUESTEER tag `[⚠ arXiv:2510.06370, EVALUESTEER]` **wraps across a line
   break** (v0 lines 151→152), so it is easy to miss when eyeballing. **The correct ⚠ figure is 42.**

4. **The two upgraded specs were never in the v0 ledger.** FC-15's "one upgrade available immediately"
   targets *citations to the two public specs* (OpenAI Model Spec, Claude's Constitution). Auditing v0
   shows the spec **documents themselves carry no citation tag** — they appear only as untagged
   narrative references. The v0 ledger's SEARCH-CONFIRMED rows that *mention* OpenAI are the **Model
   Spec Evals metric** (row S1) and the **Collective Alignment → Model Spec pipeline** (row S10),
   which are distinct artifacts and are **NOT** what the registry stamps cover. So V-1/V-2 are added
   here as new registry-evidenced rows; they do **not** subtract from the 20 SEARCH-CONFIRMED count.
