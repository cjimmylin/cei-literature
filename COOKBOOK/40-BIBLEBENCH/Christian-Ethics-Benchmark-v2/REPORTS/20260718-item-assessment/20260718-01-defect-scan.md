## 1. M1 Schema / Defect Scan — Method

M1 parses every admin line of both item surfaces (public authoring bank and holdout
bank) and applies a fixed battery of schema-integrity checks. Each check emits a defect
record tagged with a defect code and the offending `item_id`. The scan is purely
mechanical: it inspects the serialized item structure (keyed dictionary, keyed-expressed
lists, user-role message content) without invoking any model or judge.

The M1 defect vocabulary observed in this run consists of a single fired code:

- `KEYED_EMPTY` — the item's `keyed` dictionary is present but carries only empty
  values (an all-empty keyed dict), meaning the item declares no scorable keyed
  behavior.

### 3.3 design-05 budget=0.0 census

The budget check inspects `metadata.keyed.extras.allocation.budget` for every design-05
(`ordoamoris`) allocation item and flags `budget == 0.0` or a missing budget field. For
`WW-05-E03` specifically, the check further compares the metadata budget against the
session count stated in prose.

Verbatim census total: **8 hits** (5 public + 3 holdout).

**Public design-05 budget=0.0 items:**

| item_id | issue |
|---------|-------|
| WW-05-E03 | budget=0.0 in metadata but prose specifies a session count (prose mention = "8") |
| WW-05-L01 | budget==0.0 in extras.allocation |
| WW-05-E04 | budget==0.0 in extras.allocation |
| WW-05-E01 | budget==0.0 in extras.allocation |
| WW-05-F01 | budget==0.0 in extras.allocation |

Plus **3 holdout design-05 items** (aggregate only; IDs withheld) — bringing the census
to the verbatim total of 8. The dispatch's "3–4 holdout" characterization resolves to
exactly 3 holdout budget=0.0 hits per the verification pass.

`WW-05-E03` is the specific mismatch case: the allocation budget is stored as `0.0` while
the item's prose specifies a session count ("8"), so the stored allocation ceiling does
not reflect the intended allocatable quantity. The remaining public members carry
`budget == 0.0` in `extras.allocation` (allocation asks present in prose — e.g. "allocate
the 3 days", "allocate the 10 units", "allocate the 4 hours", "allocate the 9 seats" —
but the numeric budget field not populated in metadata). This is the mechanical
signature behind the design-05 CSR-unscorable / allocation-spec issue tracked elsewhere
in the assessment.
