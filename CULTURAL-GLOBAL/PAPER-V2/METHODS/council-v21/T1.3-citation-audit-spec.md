## Problem

Reference tracking has collapsed into ad-hoc fuzzy regex matching with a 15–20% false-positive risk. APA prose contains 7+ distinct citation forms (parenthetical, narrative, possessive, et al. collapse, suffixes). Multi-author papers with 6+ authors trigger automatic "et al." on first cite, breaking author-name matching. Year suffixes (a/b) cannot be disambiguated by naive grep. The plan must produce staged JSON bins (Matched / Uncertain / Orphan), not auto-deletion.

## Existing Tooling

Found `CEI-Lit-WS/PYTHON/smart_citation_cleanup.py` — handles YAML metadata citation counts, NOT prose audit. **No existing prose-to-reference matching engine.** Build `audit_references.py` from scratch; design as importable module for reuse.

## audit_references.py Specification

```python
"""
Parses 09-references.md → structured dict of references.
Scans prose .md files → extracts candidate citations.
Classifies into Matched / Uncertain / Orphan with confidence scores.
NO deletion — flagging only.
"""

# Reference dict shape:
# {
#   'Alyemny_2023a': {
#     'first_author_lastname': 'Alyemny',
#     'year': 2023,
#     'suffix': 'a',
#     'all_author_lastnames': ['Alyemny'],
#     'full_entry': '...',
#   },
#   ...
# }

# Citation regex (handles 9 prose forms):
CITATION_PATTERNS = [
    r'\(([A-Z][a-z]+(?:[-\u2019\']?[A-Z][a-z]+)*)(?:\s+et\s+al\.?)?,?\s+(\d{4})([a-c])?\)',  # parenthetical
    r'([A-Z][a-z]+(?:[-\u2019\']?[A-Z][a-z]+)*)(?:\s+et\s+al\.?)?(?:\'s)?\s+\((\d{4})([a-c])?\)',  # narrative
    r'([A-Z][a-z]+)\s+and\s+([A-Z][a-z]+)\s+\((\d{4})([a-c])?\)',  # two-author conjunction
    r'([A-Z][a-z]+)\s+and\s+colleagues\s+\((\d{4})([a-c])?\)',  # "and colleagues"
]

def classify(candidate, refs_dict):
    """Returns (bin, confidence, matched_key_or_None)."""
    # Exact match → Matched (1.0)
    # Single candidate, partial author match → Matched (0.9)
    # Multiple candidates with same (author, year) → Uncertain (0.6)
    # Year-suffix ambiguity (no suffix in prose, multiple a/b refs) → Uncertain (0.7)
    # No candidate found → Orphan (0.0)
```

## Bin Definitions

- **Matched (≥0.9):** First-author lastname + year exact match, no a/b ambiguity, exactly one candidate ref
- **Uncertain (0.5–0.9):** Year-suffix ambiguity, OR multiple candidate refs share (first_author, year), OR partial author match (et al. unverified against full roster)
- **Orphan (<0.5):** Zero candidate refs match prose citation; flagged for human review, NOT deleted

## Bidirectional Pass Spec

- **Pass A — refs → prose:** For each entry in 09-references.md, search all prose files for at least one citation. Output: `citations_audit_refs_to_prose.json` listing `{reference_key, found_in_files, found_forms, confidence}`
- **Pass B — prose → refs:** For each prose citation extracted, attempt to match a reference. Output: `citations_audit_prose_to_refs.json` listing `{prose_citation, matched_reference_key, confidence, bin, file:line}`

Both passes share the matching engine; outputs are separate JSON files. Orchestrator merges for review.

## Edge Cases T2.3 MUST Handle

- "et al." in first cite for 3+ author papers (default APA 7th edition)
- Possessive forms: `Smith's (2020)`, `the Smith and Jones (2020) position`
- Narrative integration: `as Smith and Jones (2020) argue`
- Year suffixes: `(2023a)` vs `(2023b)`; ambiguous `(2023)` with multiple candidates
- Same first-author + same year (no suffix) = ambiguous
- Hyphenated author names: `von Fintel`, `de Vries`
- Non-ASCII characters: `López` ≈ `Lopez` (use `unicodedata.normalize`)
- Year-only orphans: `(2020)` with no author — flag as Orphan (low confidence)
