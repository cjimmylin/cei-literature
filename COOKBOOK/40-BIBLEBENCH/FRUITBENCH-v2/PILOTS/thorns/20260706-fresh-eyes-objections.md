# THORNS (v2-02) — Fresh-Eyes Builder Objections (FO-8a)

**Author:** Opus build session, 2026-07-06 · **Written BEFORE implementing** (gate order FO-8a).
**Purpose:** a builder's objections to the THORNS brief as written, filed for the second-pass Fable gate (FO-8, due after 3 P1 pilots). Not a plan; the build proceeds regardless per the vault EXECUTE rule. Each objection carries this session's disposition.

1. **The entire P1 gate battery presupposes live multi-vendor runs — and this environment is credential-blocked.** Attraction calibration ("3 open models + 1 persona-prompted attacker"), the 3-model pilot, D-21 held-out-frontier transfer, and D-22 CFT liveness are all *empirical thresholds on model behavior*. No API keys are present (only the Anthropic SDK; no OpenAI). → *Disposition:* build the items + feasibility map + harness **for real** and runnable; exercise the harness on a documented **synthetic reference-response model** labeled harness-validation-only; flag the real multi-vendor run as the single gated remaining step. No synthetic number is reported as an empirical finding.

2. **D-21 transfer is only meaningful if the held-out frontiers are a *different family* than both the calibration ensemble and the eval set.** The brief says "held out from evaluation" but not "held out from the calibration family." Two same-vendor frontiers can share the calibration model's blind spots, so >5% transfer would prove little. → *Disposition:* harness records a `family` field per model; transfer check asserts cross-family disjointness and refuses to certify otherwise. Recommend Fable tighten the brief wording.

3. **The calibration band (40–80% baseline W-take-rate) has an unfrozen degree of freedom: persona strength.** Take-rate is a property of the attacker-persona prompt as much as of the item; a stronger jailbreak persona pushes *every* item toward the ceiling, silently moving items in/out of band. The brief freezes the *ensemble* but not the *persona-strength*. → *Disposition:* freeze the attacker persona text as a versioned harness artifact (`HARNESS/shared/attacker-persona-v1.md`); band is defined against that frozen persona; re-norming requires a new persona version.

4. **D-22 CFT-liveness and the W-band are in mechanical tension.** A persona strongly attracted to the W-path (needed for a 40–80% W-take-rate) will rarely also take the *milder* CFT counterfeit. Two independent ≥-thresholds can be jointly unsatisfiable. → *Disposition:* treat calibration as a *joint* target (W-take in band AND CFT-take ≥5%), report the joint-feasible fraction, and flag any cell where the two compete as a re-engineering candidate rather than silently passing one.

5. **Trichotomous scoring (Fi / Wj / CFT) forces a single label onto responses that mix** — the brief's own §A4 "F6 correction in a W9 register" is a mixed event. Forcing one of three discards the most diagnostic cases. → *Disposition:* scorer emits **four** buckets (Fi / Wj / CFT / mixed-other) plus the separate 0–4 quality-of-Fi rubric; the trichotomous headline is computed with `mixed` explicit, never collapsed.

6. **Several cells risk construct-bleed onto neighboring designs, exactly as the falsification conditions warn.** F4×W9 vs v1 LONGFUSE, F9×W15 vs v1 MARSHMALLOW, and F2×W15 vs F9×W15 (joy-frenzy vs self-control-frenzy) can collapse (r>0.9). The convergence checks that would catch this need live runs. → *Disposition:* the feasibility map flags these as "convergence-watch" cells; the pilot cannot run the r-checks without credentials, so they are declared pending, not passed.

7. **Some grid cells are near-infeasible without violating the beat-2 "no naked villainy" rule.** F8×W14 (gentleness vs annihilating/"murder-analogue" speech) can rarely be made an *attractive instrumental* path in a realistic task. → *Disposition:* the feasibility audit declares such cells infeasible/forced with reasons rather than faking quota; W14 is used only in its documented limit-case sense with a sympathetic-pressure framing, or dropped.

8. **Eval-awareness: the recipe is public and self-revealing.** A model that has read the THORNS paper knows every item hides a live W-attractor and a CFT escape hatch; "this is a temptation test" pattern-matching inflates pass rates. The brief asserts incidental embedding but does not verify it. → *Disposition:* run the authoring-conventions §8 anti-shortcut audit (cheap classifier + ablated-last-turn probe) on the 60 items; leaked features get rewritten. (Classifier audit is code-only and runs without model credentials.)

9. **"Never norm on evaluated models" + "held-out frontier transfer" jointly demand a disjoint model pool the environment may not supply.** With a small available pool, calibration/eval/held-out disjointness can be infeasible; the brief gives no fallback. → *Disposition:* harness makes the three roles explicit config lists and **fails loud** if they overlap, rather than silently reusing a model across roles.

10. **No human anchor exists for "attractive."** Calibration equates "the W-path is a live temptation" with "a jailbroken model takes it" — that is a model artifact, not evidence a human agent would feel the pull. → *Disposition:* the FO-5 shared human-substitution protocol (this session ships the spec at `HARNESS/shared/`) explicitly names THORNS-calibration as a consumer; program law stands — no headline rests on simulated take-rates alone.

11. **Minor tripwire (resolved):** the brief/build-guide cite "KB docs 01/04/07" without a path; they live at `COOKBOOK/00-KNOWLEDGEBASE/`, not under `FRUITBENCH/`. The flagged verbatim evidence numbers (MORALSIM 7.9–76.3%; sycophancy −66.8%; NurValues 90%→32.29) live in `30-EVIDENCE/20260705-cards/`, not the digests — the digests summarize. Both re-located this session; they matter at paper flesh-out, not at P1.
