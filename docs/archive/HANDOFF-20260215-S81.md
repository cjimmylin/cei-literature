## Appendix B: YAML Safety Rules (CRITICAL)

### 1. NEVER Round-Trip YAML

```python
# DESTROYS list-based fields (tags, authors)
fm = parse_frontmatter(text)
fm['new_field'] = 'value'
text = rebuild_frontmatter(fm)

# Safe regex replacement (preserves ALL other fields)
re.subn(rf'^{re.escape(key)}:.*$', f'{key}: "{value}"',
        frontmatter, count=1, flags=re.MULTILINE)
```

### 2. Quote Handling

```python
# Causes odd quote count -> validation failure
value = f'She said \\"hello\\"'

# Replace double quotes with single quotes
value = original.replace('"', "'")
```

### 3. Always Validate After Batch Changes

```bash
../.venv/bin/python PYTHON/validate_all_papers.py
```

### 4. The Parser is Regex-Based

`parse_frontmatter()` only handles flat `key: value` pairs — it is NOT PyYAML. It cannot handle nested YAML, multi-line values, or YAML arrays.

## Appendix E: Agent Swarm Pattern

This vault heavily uses parallel agent swarms for enrichment. The standard pattern:

1. **Batch generation script** divides work into N batch files (JSON), each with ~25-100 paper references
2. **Launch N agents** in waves of 5 (avoid rate-limit cascades)
   - Each agent reads its batch file + each paper's PDF extract
   - Writes results to `logs/YYYYMMDD-{task}_agent_NN.json`
3. **Monitor progress:** Check which agent output files exist
4. **Consolidation script** merges all agent JSONs, applies changes to paper YAML
5. **CRITICAL: Always run a sequential mop-up pass** on the full range after parallel batches (catches ~5-7% stragglers from stdout buffering)

**Parallel write safety:** Use PID-scoped temp files for concurrent JSON writes:
```python
tmp = f".tmp.{os.getpid()}.json"
# write to tmp, then:
os.replace(tmp, final_path)  # atomic
```

**Forced stdout flush** (prevents lost output in parallel runs):
```python
import functools
print = functools.partial(print, flush=True)
```
