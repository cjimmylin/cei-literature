## Exact blocker

The first Pilot 2 TDD implementation pass represented the approved five-model roster,
provider pins, reasoning controls, 8,192-token ceiling, geometry, dynamic judge byte
envelopes, and non-quotable reporting boundary. Focused tests passed 19/19 and the complete
offline suite passed 845/845.

Fresh specification review nevertheless failed on four P1s. Three are mechanical
(public-preflight packet, live-run custody, and OAuth-canary custody). The fourth cannot be
fixed without an owner-approved judge-output contract:

- The current Codex-OAuth adapter returns one Boolean `satisfied` for OPEN/EPISODE or one
  `satisfied` / `not_satisfied` / `ungraded` enum for CONTESTED.
- The existing scorers require richer route-specific outputs: OPEN keypoint award maps and
  numeric Matter/Manner/End levels; CONTESTED disclosure awards, position and defensibility,
  numeric coherence, and settled-core votes; EPISODE multiple rubric-keypoint votes.
- No binding rule maps the current Boolean/enum to those richer values. Inventing such a
  mapping would change scoring semantics.

The permitted named-blocker fix cycle therefore stopped before making any fix. The
zero-paid public preflight was not run, so no Pilot 2 catalog snapshot, executable manifest,
refreshed cap, credential access, OAuth task, inference call, or spend exists.

## Requested ruling

Authorize one of these new-study contracts:

1. **Route/call-specific structured schemas (recommended).** Preserve the registered
   1,740 logical judge decisions and define one schema for each existing scorer call type,
   returning exactly the award maps, legal numeric levels, position labels, defensibility,
   and rubric votes those scorers already parse. This changes transport shape only; it does
   not change scoring arithmetic or the frozen bank.
2. **Expanded atomic records.** Turn every keypoint, axis, and position field into a
   separate judge record, then refresh logical-decision geometry, OAuth task count, byte
   ceilings, and runtime forecast before any preflight. This is mechanically simpler but
   expands the registered protocol.

**Suggested default:** authorize option 1. It preserves the study's approved 1,740-decision
geometry and existing scorer semantics while making the judge transport explicit.
