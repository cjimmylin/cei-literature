# Methods: Dashboard v4 Visual QA and Bug Remediation

**Date:** 2026-04-05
**Project:** `CEI-Lit-WS/MORAL-PSYCH/`

## Data and Materials

The dashboard (MPBench v4 — "The Triple Bind") is a static single-page application comprising four files: `index.html`, `app.js` (2,200+ lines), `charts.js` (1,150+ lines), `data.js` (21,000+ lines, 555KB), and `style.css`. Annotations are authored in `_tab_annotations.py` (1,780+ lines) and injected into `data.js` via a Python extraction pipeline.

The dashboard renders 30+ ECharts visualizations across 10 tabs (with 3 sub-tabs in the Explorer tab), a 292-row sortable/filterable ranking table, a 17-feature × 292-benchmark heatmap matrix, and 40+ annotation blocks with disciplinary perspective attributions.

## Procedure

### Phase 1: Systematic Visual QA

A Playwright-driven browser automation audit was conducted across all 10 top-level tabs and 3 Explorer sub-tabs. For each tab:

1. The tab was activated via Playwright's `click()` on the Bootstrap tab element.
2. Console messages were captured via `browser_console_messages` (level: error).
3. A full-page screenshot was taken for visual inspection.
4. Chart container dimensions and ECharts instance states were queried via `page.evaluate()`.

The audit identified 6 bugs across 4 files.

### Phase 2: Bug Diagnosis and Remediation

Each bug was diagnosed through browser-level inspection using Playwright's `browser_run_code` tool to query ECharts option objects, sample canvas pixel data, and inspect DOM state.

**Bug 1 (Model Cards):** Diagnosed by inspecting `DATA.modelInventory` array structure — objects used `display` property while renderer accessed `m.name`. Fallback `|| m` coerced the object to `[object Object]`.

**Bug 2 (Heatmap):** Diagnosed by sampling canvas pixels at expected cell locations — all returned `[0,0,0,0]` (transparent). Root cause: ECharts heatmap series requires numeric values in the third data element; string values cause silent render failure without errors. Confirmed by inspecting `chart.getOption().series[0].data`.

**Bug 3 (Recommendations):** Diagnosed by cross-referencing HTML container IDs (`discussion-recs-container`) against app.js function targets (`recommendation-cards-container` for overview only).

**Bug 4 (ID Mismatch):** Diagnosed by comparing HTML `id` attributes against Python annotation dict keys. The rendering dispatcher constructs IDs as `{tabPrefix}-ann-{entryKey}`.

**Bug 5 (Sub-tab Charts):** Diagnosed by checking ECharts instance existence (present), canvas dimensions (1110×400), data payload (6 bars, correct values), but canvas pixels all transparent. Root cause: Bootstrap pill sub-tabs use `display: none` on inactive panes; ECharts cannot render into zero-size containers. The `shown.bs.tab` event fires for sub-tabs but the `tabCharts` lifecycle only handles top-level pane IDs.

**Bug 6 (Ranking Filters):** Diagnosed by manually executing the filter function in `page.evaluate()` — correct results (48 for "top"). Then checked the theory filter condition: `theoryVal` of "all" is truthy and attempts to find literal "all" in `r.theories`, rejecting all rows.

### Phase 3: Annotation Expansion

Twelve empty annotation containers were identified by cross-referencing all `*-ann-*` HTML IDs (46 total) against `tabAnnotations` data keys. For each gap, a new entry was authored in `_tab_annotations.py` following the established format (chart type: what/finding/interpretation/member; card type: summary/detail/member). The annotations were extracted to JSON via Python import, then injected into `data.js` by locating and replacing the `tabAnnotations` value using brace-depth counting.

## Analysis

No statistical analysis was performed in this session. The work was exclusively bug remediation and content authoring.

Validation was performed via Playwright automation: after each fix, the page was reloaded and chart rendering was verified through a combination of screenshots, DOM inspection, and ECharts option queries. The ranking filter fix was validated by programmatically cycling through all 5 tier values and 1 theory value, confirming correct row counts (292, 48, 89, 72, 83, 67).

## Computational Environment

- **Browser automation:** Playwright MCP plugin with Chromium
- **Local server:** `python3 -m http.server 8765`
- **Charts:** ECharts 5, Bootstrap 5.3
- **Python:** 3.9+ (for annotation extraction)
- **Git:** Commits pushed directly to `main` on `github.com/cjimmylin/cei-moral-psych-dashboard-v4`
- **Deployment:** GitHub Pages (auto-deploys on push to main)

## Limitations and Decisions

1. **Direct-to-main pushes:** Bug fixes were committed directly to main rather than through PRs (except the first batch which used a PR). This was appropriate for the small, isolated fixes but bypassed code review.

2. **Annotation content authored by AI:** All 12 new annotations were generated by Claude, structured around disciplinary perspectives. The `aiDisclosure` field in the dashboard explicitly states this provenance.

3. **Sub-tab resize is a workaround:** The correct fix would be to lazily initialize sub-tab charts only when their sub-tab is first shown, rather than initializing all Explorer charts at once and resizing later. The resize approach was chosen for minimal code change.

4. **No automated regression tests:** All verification was manual via Playwright. A test suite for chart rendering and filter correctness would prevent future regressions.
