# Methods: Cross-Vendor LLM Ethics Benchmark Comparison and Expert Dashboard

**Date:** 2026-04-04
**Project:** `CEI-Lit-WS/NORM-ETHICS/`

## Data and Materials

### Source Data
Eighty trial JSON files from 10 normative ethics benchmarks (T6-T15) administered to 8 LLM models across 3 vendors:

| Vendor | Models | Trial Files | Location |
|--------|--------|-------------|----------|
| Anthropic | Claude Sonnet 4.6, Claude Haiku 4.5 | 20 | `STATISTICS/` (root) |
| Google | Gemini 3.1 Pro, 2.5 Pro, 2.5 Flash, 2.5 Flash-Lite | 40 | `STATISTICS/gemini-*/` |
| OpenAI | GPT-5 (Codex agent), GPT-5-mini (Codex agent) | 20 | `Codex/results/`, `Codex/mini/results/` |

Additionally, Claude Opus 4.6 was included as a metric-level baseline from the prior cross-model comparison JSON (`STATISTICS/20260404-normeval-cross-model-comparison.json`). Opus had no per-item trial files, only aggregate metrics.

### Benchmarks
Ten benchmarks spanning knowledge items (T6 PrinciplismQA, T9 JETHICS, T11 MedEthicsQA, T15 ProMoralBench) and judgment items (T7 Moral Persuasion, T8 AMAeval, T10 Pluralistic Gap, T12 UniMoral, T13 Greatest Good OUS, T14 PNAS Cognitive Biases). Total comparable items: 114 across all trials.

### Pre-existing Infrastructure
- Master comparison JSON: `COMPARISON/20260404-normeval-all-models-comparison.json` (generated by `generate_normeval_all_models_comparison.py`)
- Master comparison report: `COMPARISON/20260404-normeval-all-models-summary.md`
- Existing 9-tab ECharts + Bootstrap 5.3 dashboard at `DASHBOARD/`

## Procedure

### Phase 1: Council Assembly and Analysis

A 12-member interdisciplinary expert council was assembled to analyze the cross-vendor benchmark data. Council composition spanned RLHF/alignment training, moral psychology, psychometrics, ML systems, Kantian ethics, consequentialist ethics, AI policy, benchmark security, cross-cultural psychology, biostatistics, educational measurement, and science communication.

The council analyzed seven cross-cutting findings identified in the comparison data:
1. Three ethical profiles (Conservative/Moderate/Permissive) across vendors
2. Gemini model identity (100% pairwise agreement across 4 Google models)
3. Universal knowledge ceiling (100% accuracy on 4/10 benchmarks for all 8 models)
4. Knowledge-judgment divergence as a cross-vendor construct
5. GPT-5 as the most conservative model tested (IH=2.93)
6. Cross-vendor agreement clustering by ethical profile
7. Non-monotonic persuasion resistance patterns

Each finding was analyzed by 2-4 relevant council experts. Council votes were recorded with named dissents. The analysis was written as a 5,654-word deliberation document with executive summary, finding-by-finding analysis, methodological concerns, deployment implications, 10 consensus recommendations, and 3 dissenting views.

### Phase 2: Dashboard Data Generation

A Python script (`generate_cross_vendor_dashboard_data.py`) was created to transform the master comparison JSON into a JavaScript data constant (`DATA_CROSS_VENDOR`) for browser-side rendering. The script:

1. Read `20260404-normeval-all-models-comparison.json` for per-trial metrics and pairwise agreement
2. Read `20260404-normeval-cross-model-comparison.json` for Opus baseline metrics
3. Constructed an 8×8 symmetric pairwise agreement matrix from 28 aggregate pairwise entries
4. Built IH and CBR arrays with Opus prepended as a 9th model (metric-only)
5. Computed knowledge-judgment divergence ranges (min/max agreement per trial)
6. Normalized provider radar profiles to 0-100 scale across 6 dimensions
7. Extracted primary metrics per trial for the comparison table
8. Output valid JavaScript as `const DATA_CROSS_VENDOR = {...};` (10,259 bytes)

### Phase 3: Dashboard Tab Integration

Tab 10 ("Cross-Vendor") was added to the existing 9-tab dashboard following the established "fat data, thin client" architecture:

- **HTML** (`index.html`): Tab nav link, tab pane with explainer, KPI cards, 5 chart containers, findings list, per-trial table
- **Charts** (`charts.js`): 5 ECharts render functions + orchestrator (`renderCrossVendorCharts`)
- **App logic** (`app.js`): `renderCrossVendorTab()` for DOM elements, lazy tab listener for chart initialization
- **Data** (`data_cross_vendor.js`): Loaded via separate `<script>` tag

### Phase 4: Council Review and Improvements

The council reviewed the completed dashboard and identified 7 improvements:
1. Subtitle precision ("9-model / 3-vendor")
2. Heatmap vendor labels using ECharts `graphic` component
3. "Effective Profiles" KPI replacing redundant "Highest Cross-Vendor"
4. IH and CBR charts sorted ascending for visual gradient clarity
5. Opus baseline footnote for first-time readers
6. Metric name column in per-trial table for interpretability

### Phase 5: Full-Dashboard Expert Annotations

Expert analysis blocks were added to all 10 tabs (30 blocks total). Each block followed a consistent format: colored left border, named expert attribution with discipline, "What to observe" / "Interpretation" / "Conclusion" structure. Expert voices were matched to their disciplinary expertise (e.g., Dr. Fischer on Kantian analysis, Dr. Voss on RLHF implications, Dr. Tanaka on Western bias).

### Phase 6: Deployment

Updated files were copied to the `cjimmylin/cei-normeval-dashboard` GitHub Pages repository and pushed in three commits. GitHub Pages was configured for legacy deploy-from-branch mode (auto-deploy on push to `main`).

## Analysis

### Pairwise Agreement Computation
Agreement was computed at the item level using `comparable_value()` extraction per trial type (MCQ response, Likert rating, binary judgment, etc.). For each of 28 model pairs across 114 items, agreement = (items with identical responses) / (total comparable items). The resulting 8×8 matrix was symmetric with diagonal = 100%.

### Provider Profile Normalization
Six ethical dimensions were normalized to a 0-100 scale for radar chart comparison:
- IH Acceptance: ((value - 1) / 6) × 100 (raw scale 1-7)
- CBR Rate: raw percentage (0-100)
- Persuasion Resistance: 100 - decision_change_rate
- Knowledge Accuracy: raw percentage (T6 representative)
- Kohlberg Stage: ((stage - 1) / 5) × 100 (stages 1-6)
- Altruism Rate: raw percentage

### Chance-Corrected Agreement
Dr. Lindström computed Cohen's κ for selected pairs: Sonnet-GPT-5 κ ≈ 0.72 ("substantial"), GPT-5-Haiku κ ≈ 0.18 ("slight"). Base rate estimation used the marginal frequency of majority responses across binary/categorical items.

## Limitations and Decisions

1. **Opus as metric-only baseline:** Opus 4.6 had no per-item trial JSONs, only aggregate metrics from the prior Claude cross-model comparison. It appears in bar charts but not in the pairwise heatmap, which requires item-level data.

2. **Codex agent wrapper confound:** GPT-5 and GPT-5-mini were tested via the Codex agent interface, not the standard OpenAI API. The agent wrapper may introduce additional safety filtering or system prompts that alter the model's baseline ethical responses.

3. **Single administration (n=1):** All trials were single-administration with no variance estimation. The IH=4.47 for Haiku/Gemini is a point estimate without confidence intervals.

4. **Item count limitations:** T7 (Persuasion) has only 3 items — a single item flip changes the rate from 0% to 33.3%. The council noted this in Finding F7 (8/12 consider real but fragile).

5. **Western benchmark bias:** All 10 benchmarks are Western in origin and normative grounding. Cross-cultural validity is untested.

6. **Temperature setting:** All trials used temperature=0 (deterministic). The council recommends testing Gemini at temperature>0 to distinguish shared infrastructure from deterministic convergence (Recommendation #2).
