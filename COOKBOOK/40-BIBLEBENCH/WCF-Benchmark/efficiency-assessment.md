4. **Release-grade / quotable benchmark — NOT complete.** Human-panel and registered T4/G1–G7 gates remain separate, owner-gated work. PPP-1 does not satisfy or amend them.

The ledger's reconciled mean is **3.64/5**. Thirty-one of 45 sessions scored 4 or 5, so most work was substantively useful. The main efficiency failure was sequencing, not technical ability: authoring ran ahead of executable custody; judge validity was learned through repeated live cycles that better fixtures and persistence could have compressed; and S29–S34 became an explicit six-session shadow-study detour with 29 WCF-scoped commits but no production panel, manifest, T4, score, or paper effect. The strongest pattern was the opposite: persist evidence, read it at sample level, decide only what blocks validity, and produce a paper-facing artifact in the same session.

The fastest credible next move is not more runner work. It is one separately authorized, zero-paid, paper-only assembly session that turns the accepted PPP-1 packet and existing pre-draft into one coherent, traceable, visually verified exploratory manuscript and PDF.

## Audit method, rubric, evidence, and limits

This audit treats `project-dashboard.html` as the canonical session ledger. It covers **45 labels**, not 42: S1–S42 plus S1b, S5b, and S35-P. Ratings are retrospective judgments against the **shortest credible path to the accepted exploratory MVP**, not judgments of effort, intelligence, or technical competence.

| Score | Retrospective class | Meaning |
|---:|---|---|
| 5 | Decisive | Produced a paper/evidence/MVP gate or directly crossed it. |
| 4 | Strong necessary | Made a necessary contribution or removed a material P0/P1 blocker. |
| 3 | Useful enabling | Advanced the path but did not itself produce or unlock the headline artifact. |
| 2 | Indirect / overhead / late | Useful administration or technically relevant work sequenced later than the shortest path required. |
| 1 | Detour | Little or no consumable effect on the accepted exploratory MVP. |

Primary evidence is the dashboard's frozen S1–S42 history, LIVE status, progress, path-to-paper, critical path, budget, and update log. The assessment also uses dashboard-recorded run sizes, costs, gate states, allocations, and explicit no-effect statements. Engineering line counts may illustrate proportionality—`episode_run.py` plus its test is 2,243 lines, the shadow bakeoff plus tests is 4,689, and PPP-1 runner plus tests is 1,740—but line counts are only a proxy, never proof of waste.

Limits: sessions differ greatly in duration and team size; early work operated with less information; the ledger compresses within-session retries and parallel work; and counterfactual sequencing cannot prove that the same result would have been achieved on the first attempt. Scores therefore evaluate consumable effect and ordering, not moral blame.

## Characteristics of true needle-moving sessions

The score-5 sessions share five traits:

- They cross a named sufficiency gate or deliver evidence/manuscript content usable immediately.
- They use persisted evidence and sample-level reading rather than treating test volume as progress.
- They resolve a validity blocker without broadening scope.
- They combine stages that naturally belong together: run plus paper packet, or owner decision plus acceptance record.
- They stop at the acceptance ceiling. S28 skipped optional polish; S35 corrected offline instead of rerunning; S41 recorded cell errors and continued.

## Rabbit-hole signatures and root causes

1. **Authored is mistaken for executable.** S1–S5 accumulated breadth before the serialization/loader/runner path was complete.
2. **Live calls substitute for adversarial fixtures.** S7–S14 discovered quote parsing, response insensitivity, repeatability, hashing, auth, and retry requirements serially.
3. **Infrastructure becomes the deliverable.** Tests and code volume can secure validity, but they do not substitute for a paper claim. The 4,689-line shadow implementation-plus-test surface is a proportionality warning, not proof by itself.
4. **Governance is split into its own sessions.** S19, S25, and S32 could have been folded into substantive closure.
5. **A bounded side study still consumes the critical path.** Scope caps did not make S29–S34 relevant to the exploratory MVP.
6. **Later-stage rigor is sequenced before the immediate milestone.** S23 was valuable preregistration; S37 was valid preflight; neither should displace the exploratory manuscript path.
7. **Review transactions multiply.** Review is useful when it finds a real P0/P1, as in S39, but specifications, fixes, re-reviews, governance checks, and handoffs must be folded and capped.

Root causes were unclear state naming, insufficiently explicit paper-facing session contracts, late persistence/custody requirements, and failure to require each session to **RUN, WRITE, or DECIDE** toward a named artifact or named P0/P1.

## Future learning and actions

The useful governance unit is a tiny session contract embedded in the dashboard or handoff, not a new subsystem. A future example:

```json
{
  "session": "S44",
  "mode": "WRITE",
  "paper_milestone": "Integrated exploratory manuscript and PDF",
  "sufficiency_gate": [
    "all result claims trace to accepted PPP-1 evidence",
    "exact exploratory/single-judge/non-quotable label retained",
    "PDF visually verified"
  ],
  "named_artifact": "08-PAPER/20260714-mvp-exploratory-paper/manuscript.pdf",
  "p0_p1_removed": "PPP-1 integration gap",
  "timebox_hours": 8,
  "spend_cap_usd": 0,
  "forbidden": ["model_calls", "runner_changes", "bank_edits", "manifest_changes", "overwrite"],
  "stop_condition": "one P0/P1 review and one correction cycle completed"
}
```

A minimal no-dependency validator could later be:

```python
#!/usr/bin/env python3
import json
import sys
from pathlib import Path

REQUIRED = {
    "session", "mode", "paper_milestone", "sufficiency_gate",
    "named_artifact", "timebox_hours", "spend_cap_usd",
    "forbidden", "stop_condition",
}

def main(path: str) -> int:
    data = json.loads(Path(path).read_text(encoding="utf-8"))
    missing = sorted(REQUIRED - data.keys())
    errors = []
    if missing:
        errors.append("missing: " + ", ".join(missing))
    if data.get("mode") not in {"RUN", "WRITE", "DECIDE"}:
        errors.append("mode must be RUN, WRITE, or DECIDE")
    if not data.get("named_artifact") and not data.get("p0_p1_removed"):
        errors.append("name an artifact or a removed P0/P1")
    if not isinstance(data.get("sufficiency_gate"), list) or not data.get("sufficiency_gate"):
        errors.append("sufficiency_gate must be a non-empty list")
    if data.get("timebox_hours", 0) <= 0 or data.get("spend_cap_usd", -1) < 0:
        errors.append("timebox must be positive and spend cap non-negative")
    if errors:
        print("INVALID: " + "; ".join(errors), file=sys.stderr)
        return 1
    print("VALID")
    return 0

if __name__ == "__main__":
    raise SystemExit(main(sys.argv[1]))
```

Do **not** implement this validator until after the MVP exploratory paper. The present dashboard gate is sufficient for the next session. The immediate learning is behavioral: every session must **RUN, WRITE, or DECIDE**, close with a named paper artifact or named P0/P1 removal, and fold/defer otherwise.
