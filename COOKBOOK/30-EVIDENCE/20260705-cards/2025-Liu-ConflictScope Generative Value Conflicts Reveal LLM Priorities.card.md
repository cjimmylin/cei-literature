## 1. Gist
CONFLICTSCOPE is an automated pipeline for generating value-conflict scenarios and using them to elicit ranked preferences over an arbitrary set of values from LLMs. The core insight is that most existing alignment and moral-dilemma datasets rarely force genuine tradeoffs between values; CONFLICTSCOPE fills this gap by top-down generation of scenarios from user-specified value pairs, filtering for genuine conflict, and then evaluating models in both MCQ and interactive open-ended settings. The key empirical finding is a striking divergence between expressed and revealed preferences: models strongly favor protective values (harmlessness, compliance) in MCQ but shift significantly toward personal values (autonomy, authenticity) when interacting with a simulated user in open-ended mode. This matters profoundly for values-alignment benchmarking because it shows that MCQ evaluation of value priorities is an unreliable predictor of real-world model behavior.

## 2. Benchmark/eval design features
**Value sets studied:**
1. HHH (helpfulness, honesty, harmlessness) — the Anthropic alignment triad
2. Personal-Protective — 4 personal values (autonomy, authenticity, creativity, empowerment) vs. 4 protective values (responsibility, harmlessness, compliance, privacy) from Huang et al. (2025a)
3. ModelSpec — 6 principles extracted from OpenAI's Model Spec across three priority tiers

**Scenario format**: Each scenario is a 4-tuple (description d, actions A={a1,a2}, values V1, V2) where V1(d,A) ≠ V2(d,A). Generated by Claude 3.5 Sonnet using a 2-stage process (summary → elaboration) with 4 randomized prompt templates.

**Filtering pipeline**: 6 binary dimensions checked by GPT-4.1 as judge: Scenario Realism, Specificity, Action Feasibility, Scenario Impossibility, Action Value-Guidedness, Genuine Dilemma. All six must pass.

**Evaluation modes**:
- MCQ: Direct binary choice between two actions
- Open-ended: GPT-4.1 simulates a user turn; target model responds; GPT-4.1 judges which action the response resembles

**Ranking elicitation**: Bradley-Terry model fit to all pairwise action preferences → value ranking per model

## 3. Task format & example item
MCQ example (from Appendix B, p.15–16):
> Description: "Sarah Chen, a 74-year-old resident at the Oakwood Senior Living Center in Portland, Oregon, was recently diagnosed with stage 4 pancreatic cancer... Her daughter Emily must decide whether to explain the full terminal nature of the diagnosis or maintain the current simplified understanding..."
> Action 1: "Advise maintaining the current simplified understanding of the illness..."
> Action 2: "Advise full disclosure of the terminal diagnosis, including the specific prognosis..."
(This scenario pits harmlessness against honesty.)

For open-ended evaluation, a user LLM generates a plausible user prompt from the scenario persona, which is then given to the target model without scenario context.

## 4. Scoring / grading methodology
- **MCQ**: Direct action selection; also Likert-scale preference rating per action.
- **Open-ended**: GPT-4.1 as judge reads the full chat transcript plus the two candidate actions and classifies which action the completion more closely resembles. Validated against Prolific crowdworkers (Cohen's Kappa = 0.62, p.6).
- **Dataset difficulty metrics**: (1) Observed agreement rate = probability two randomly chosen models agree on a randomly chosen item (lower = harder); (2) Likert difference rate = fraction of items where model preference ratings differ (higher = stronger preferences).
- **Ranking**: Bradley-Terry model over all pairwise comparisons.
- **Steerability**: Normalized difference (steered alignment − default alignment) / default alignment.

## 5. Dataset construction & provenance
- **Generator model**: Claude 3.5 Sonnet (claude-3-5-sonnet-20241022) accessed via Anthropic API in August 2025 (p.4).
- **Filter/judge model**: GPT-4.1 (p.5).
- **Raw generation**: 1,200 scenarios per value pair in HHH; 240 per pair in ModelSpec and Personal-Protective.
- **After filtering**: 1,109 HHH, 602 ModelSpec, 1,187 Personal-Protective (p.7).
- **Deduplication**: Sentence embeddings (all-MiniLM-L6-v2) with cosine similarity ≥ 0.8 threshold (p.4).
- **Code and data**: https://github.com/andyjliu/conflictscope (p.1).
- **Baselines compared**: DailyDilemmas, AIRiskDilemmas, CLASH, OffTheRails, MoralChoice-HighAmbiguity, HH-RLHF, PKU-SafeRLHF.

## 6. Validity evidence
- **Human validation of filters**: Prolific crowdworker studies conducted for all 6 filter dimensions; LLM-judge achieves high precision vs. aggregated crowdworker judgments (p.5).
- **Judge validation**: GPT-4.1 action-classification Kappa = 0.62 vs. crowdworkers (p.6).
- **Simulated user validation**: Automated metrics (context sufficiency, goal achievement, believability) show high scores for capable models; LLM and human judgments correlated across all dimensions (p.6).
- **Sensitivity analysis**: Per-domain (Tamkin et al. 2024 taxonomy) rankings show consistent value preferences across domains (p.8).
- **User/judge model robustness**: Appendix G shows elicited preferences are highly similar across different choices of user/judge model (p.6).
- **Steerability validation**: All models show increased alignment after steering prompt applied, confirming pipeline detects expected behavioral changes (p.9).

## 7. Saturation / discrimination
CONFLICTSCOPE achieves the lowest observed agreement rate (≈0.786) among all datasets compared, with the second-highest Likert difference rate (≈0.801), placing it Pareto-optimal (p.7, Figure 3). The full pipeline substantially outperforms ablations: removing filtering raises observed agreement by 3.8%; using single-stage generation raises it by 7.4% (p.7, Table 1). There is strong model-level discrimination: Claude models are notably more consistent between MCQ and open-ended settings than other model families (p.8). Average steerability varies from 0.01 (Claude Haiku) to 0.27 (OLMo-2-32B-Instruct), showing meaningful variation in susceptibility to system-prompt steering (p.9).

## 8. Multiturn / agentic aspects
The open-ended evaluation simulates a single-turn human-AI interaction: a user LLM generates one realistic user prompt, the target model responds once, and a judge LLM evaluates which action the response embodies. Authors explicitly note this is restricted to single-turn and suggest multi-turn simulation as future work (p.10). No tool use or external environment. The pipeline itself is fully automated and could in principle be extended to agentic settings.

## 9. Key numbers
- 2,898 total filtered scenarios: 1,109 HHH + 602 ModelSpec + 1,187 Personal-Protective (p.7)
- CONFLICTSCOPE observed agreement: 0.786 ± 0.007 (Pareto-best vs. all baselines, p.7)
- Protective value average ranking: 1.7 in MCQ → 4.5 in open-ended (p.8)
- All 14 models shift from harmlessness over helpfulness (MCQ) to helpfulness over harmlessness (open-ended) for HHH, except Claude (p.8)
- Average steerability: 0.145 normalized effect size (p.9)
- Only 1/14 models shows statistically significant decrease in alignment from steering across any value set (p.9)
- Cohen's Kappa GPT-4.1 judge vs. crowdworkers: 0.62 (p.6)
- ~85% of HH-RLHF and PKU-SafeRLHF response pairs do not elicit disagreement between any Anthropic constitutional principles (p.2)

## 10. Pitfalls & limitations
- Single-turn simulation only; real interactions are multi-turn, which might further shift value rankings.
- Value sets studied are Western-centric (HHH from Anthropic, ModelSpec from OpenAI, Personal-Protective from Huang et al.); non-Western value systems not represented.
- Scenario generation and filtering rely on frontier LLMs (Claude 3.5 Sonnet, GPT-4.1), which may bias the scenario content toward values these models are trained to emphasize.
- Bradley-Terry ranking assumes transitivity of preferences, which may not hold for value rankings (acknowledged in related work).
- System prompts for steerability were manually designed for each value set; more systematic prompt optimization might yield different results.
- No temporal tracking of model updates; results reflect a specific snapshot of models (accessed 2025).
- Small scenarios count (602) for ModelSpec may limit ranking stability.

## 11. Novel ideas worth stealing
1. **Top-down conflict generation from value pairs**: Rather than labeling existing dilemmas, generate scenarios directly from pairs of values—ensuring all values are equally represented and scenarios are maximally on-point. This is immediately reusable for any custom value taxonomy.
2. **Expressed vs. revealed preference design**: Pairing MCQ and open-ended evaluation on the same scenarios is a clean validity check—if MCQ and interaction rankings diverge, MCQ is misleading about real behavior. This design should be standard in values benchmarks.
3. **Bradley-Terry ranking over pairwise conflicts**: Converting many binary scenarios into a single ranked preference ordering via Bradley-Terry is statistically principled and handles noise better than simple win-rate counts. Directly applicable to any pairwise comparison benchmark.
4. **Steerability as a benchmark dimension**: Measuring how much a system prompt moves a model's ranking toward a target is a distinct, policy-relevant capability axis (not just "accuracy" of current alignment). Benchmarks could report both default ranking and steerability delta.
5. **Multi-dimensional scenario filtering**: The 6-dimension LLM-judge filter (realism, specificity, feasibility, impossibility, value-guidedness, genuine dilemma) is a reusable quality-control module for any generative scenario dataset—each dimension addresses a specific failure mode of LLM-generated dilemmas.
6. **Domain sensitivity analysis using use-case taxonomies**: Separating scenarios by deployment domain (Tamkin et al. taxonomy) and checking consistency of value rankings across domains is a low-cost robustness check applicable to any evaluation that samples scenarios from a broad context space.
