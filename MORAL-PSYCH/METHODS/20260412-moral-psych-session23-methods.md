# Methods: Multi-Round Critique-Driven Plan Refinement and Parallel Agent Execution for Dashboard Maintenance and Combined PDF Assembly

**Date:** 2026-04-12
**Project:** `CEI-Lit-WS/MORAL-PSYCH/`

## Data and Materials

The session operated on the Moral Psychology Benchmarks dashboard v4 (`DASHBOARDS/moral-psych-benchmarks-v4/`) and Paper v4 (`PAPER-v4/`), both maintained as static-site artifacts within the CEI Literature Vault. The dashboard comprises five deployed assets totaling approximately 750 KB: `index.html` (45 KB, 1,001 lines), `app.js` (78 KB, 2,243 lines), `data.js` (542 KB, 21,253 lines, machine-generated), `style.css` (32 KB), and `charts.js` (61 KB). The dashboard is generated from `generate_dashboard.py` (95 KB, 2,442 lines), which is excluded from the deployment repository via `.gitignore` and therefore lacks a version-control safety net within the local working tree. The Paper v4 corpus consists of 9 main markdown sections (1,919 total lines) and 3 supplementary sections (1,303 lines), with 15 PNG figures (2.8 MB total) in `figures/`. The deployment target is the public GitHub repository `cjimmylin/cei-moral-psych-dashboard-v4`, served via GitHub Pages.

## Procedure

The session adopted a Plan–Critique–Execute pattern with two iterative critique rounds before any code modification. An initial 6-expert design council produced an implementation plan addressing four priority items carried from Sessions 21 and 22: visual verification of three Bootstrap container fixes, creation of a combined-PDF build script, hash-based navigation quality assurance, and revision of AI disclosure language. A first 6-expert critique council (specialized in front-end SPA architecture, PDF pipelines, parallel agent safety, UX, data integrity, and test coverage) reviewed the plan and identified five high-severity issues including a lost-update conflict between two agents editing the same file, missing inline image embeds in v4 source markdown, and a synchronization gap between the data file and its generator script. The plan was revised to address these findings, after which a second 6-expert critique council (specialized in pandoc/typst pipelines, AI transparency, browser API edge cases, deployment workflows, backup discipline, and agent prompt engineering) reviewed the revision. The second council determined that a previously proposed `hashchange` event listener was dead code under the existing `replaceState`-only state management, and recommended dropping it entirely.

Following plan approval, execution proceeded in four phases. Phase 0 created `.bak-20260412` snapshot copies of all four at-risk files (including `index.html`, which had carried an uncommitted Session 22 layout fix), verified each copy with `diff`, and recorded baseline line counts. Phase 1 dispatched three parallel subagents: a visual-QA agent that started a local HTTP server on port 8765, captured nine Playwright screenshots at 1440 px and 768 px viewport widths across two tab panes, and verified hash-based deep linking against three URLs including a graceful-degradation test for an invalid hash; a PDF-build agent that adapted the v2 combined-PDF generator (219 lines, pandoc + typst backend) to the v4 section list, added prerequisite checks for pandoc and typst binaries, tightened page margins to 0.75 inches, and implemented a regex-driven figure plate appendix that parses figure entries from the supplementary figures markdown using the heading pattern `^### (Figure \d+:.+)` and the file pattern `**File:** \`(.*?)\``; and a dashboard-fix agent that updated the AI disclosure string across three files in canonical-source order (`generate_dashboard.py` line 2296, `data.js` line 20895, `app.js` lines 2147–2148) and validated the result with `grep` consistency checks and `node --check` syntax validation.

Phase 2 launched an integration-QA subagent that started an isolated HTTP server on port 8766 and executed a four-test verification sequence: hash navigation against two valid tab URLs, AI disclosure text validation via DOM extraction with substring assertions for the new wording and exclusion assertions for the old wording, multi-column container regression checks on the RLHF Fingerprint and Integrated tabs, and theme persistence verification across light/dark toggle and tab switching. Phase 3 committed the changes to the local Git working tree of the deployment repository (which already contained the correct HTTPS remote, eliminating the need for a separate clone-and-copy workflow), tagged the commit as `v4.1-s23`, and moved the four backup files to a newly created `RECYCLE-BIN/` directory in compliance with the vault-wide no-deletion safety rule.

## Analysis

The combined PDF was assembled by concatenating preprocessed markdown sections separated by `\newpage` directives, with the figure plate appendix appended after the supplementary material. The figure plate emits one figure per page using `\newpage` separators and `{width=100%}` width constraints to prevent overflow on high-resolution PNGs (range: 109 KB to 391 KB; pixel dimensions up to 3554×2085). Captions are restricted to short title-only form to avoid 30+ pages of dense extended-caption text competing with main-text content. Figure entries flagged as "Not yet generated" in the supplementary markdown (entries S16 through S19) are skipped by file-existence check before the figure plate emission. The pandoc invocation passes `--pdf-engine=typst --wrap=auto` with no `--bibliography` or `--citeproc` flags, since v4 markdown contains zero `\cite{}` markers and renders all citations as inline APA prose. Final output: a 5.29 MB PDF containing 9 main sections, 3 supplementary sections, and 15 figure plates.

The AI disclosure revision replaced a 33-word three-sentence text containing the methodologically ambiguous phrase "No human expert panel was convened" with a 29-word two-sentence affirmative disclosure that explicitly names the generating tool: "All disciplinary perspectives and interpretive analyses were generated by Claude (Anthropic) without human expert review. Quantitative data and statistical analyses are computationally derived from the source benchmarks." The revision eliminates a pre-existing inconsistency between the canonical `data.js` (which said "expert panel") and the `app.js` fallback (which said "review panel"). The three-source synchronization is verified post-edit by a `grep` for the unique substring "disciplinary perspectives" across all three files; the count must equal exactly three for the verification to pass.

## Computational Environment

The session ran in Python 3.9 within the vault's `.venv` virtual environment, requiring `from __future__ import annotations` in any new Python source to support modern type hint syntax. Pandoc 2.x and Typst 0.14.x are available system-wide and were verified by `shutil.which()` calls embedded in the new build script. Node.js was used solely for `node --check` syntax validation of edited JavaScript files. Playwright MCP provided browser automation for the visual-QA and integration-QA phases, with the documented quirk that `browser_take_screenshot` saves to the current working directory (vault root) rather than the specified destination path; this was mitigated with post-screenshot `mv` commands. HTTP serving used Python's built-in `http.server` module on isolated ports (8765 for Phase 1, 8766 for Phase 2) to prevent context contention across phases. The deployment repository is a separate Git repository nested at `DASHBOARDS/moral-psych-benchmarks-v4/.git` with an HTTPS remote; the parent vault is not itself a Git repository.

## Limitations and Decisions

The session deliberately rejected several proposed modifications that the critique councils identified as net-negative or unnecessary. The proposed `hashchange` event listener was dropped after analysis showed it would be dead code: with the dashboard's existing `replaceState`-only history management, the `hashchange` event never fires from internal navigation, and the only realistic trigger (manual URL bar editing) is exceedingly rare. The proposed change from `replaceState` to `pushState` was rejected because it would create browser history entries on every tab click, polluting the back-button stack contrary to the conventions of academic dashboards (Tableau, Observable, Flourish). The figure plate appendix was chosen over inline figure insertion at callsites because the main-text figure references use inconsistent patterns ("See Figure 9", "Figure~9", "(Figure 14)") that would require fragile regex matching and would interrupt the analytical reading flow.

The session accepted several known limitations. Hash-based navigation operates only on initial page load via `DOMContentLoaded`; in-page hash changes do not trigger tab switching. The combined PDF uses short title-only captions in the figure plate; readers must consult the supplementary figures section for full extended captions. Four supplementary-only figures (S16–S19) are listed in the source markdown but lack PNG files and are silently skipped by the build script until generated. The N=1 per model per benchmark constraint, carried from prior sessions, remains unaddressed and continues to limit inferential statistics.

The decision to perform two rounds of independent critique before execution proved decisive: Round 1 prevented a lost-update conflict between two agents editing `app.js`, Round 2 eliminated dead code that would have introduced a `TypeError` on invalid hash input, and both rounds together ensured the AI disclosure fix would survive future regeneration of `data.js` from its source generator. Total elapsed time across the planning, critique, execution, and verification phases was approximately 90 minutes, with the parallel-agent dispatch in Phase 1 completing in under six minutes for all three concurrent tasks.
