# CROSSROADS build decisions

Date: 2026-07-11. This log is contemporaneous and append-only after pilot data
exist.

1. **D-18 scoring.** Direct key-based choice profiles are primary.
   E(C1–C16) is separate. Joint Thurstonian estimation is exploratory only and
   may not run on model data until planted synthetic recovery passes.
2. **Frozen registry.** C1–C16 IDs and operational definitions are copied
   verbatim in `clause_mapping.md`; method notes specialize but do not redefine
   them. The six-family hierarchy is a reporting fallback, not an authoring
   replacement.
3. **Phase lists, not four-turn episodes.** The stored schema retains
   `stage_1..stage_4`, but each value is a turn list. Total length is 8–20 and
   stage 3 supplies 3–8 consequence/follow-through turns.
4. **Actions, not choices.** An affordance has exactly a unique
   `(tool,target,operation)` signature plus arguments and description. No
   option/path ID crosses the model boundary. Tool effects and fork time are
   authoritative.
5. **CO-3 privacy.** Tool/simulant formats are public. Branch tables, reaction
   policies, trigger thresholds, hidden parameters, and decision logic remain
   private sidecar material.
6. **Mutual blinding.** Candidate payloads contain no judge or bank identity.
   Judge payloads contain no candidate-model, item, family, split, canary,
   clause-sign, or key identity.
7. **Public qualification.** All 30 public episodes form the only qualification
   smoke set. A six-episode canary is frozen by constrained set cover of
   C1–C16, all six fallback families, and all represented substrates; ties are
   broken lexicographically by item ID. The six are reused, not rerun, in the
   30-item smoke.
8. **No sibling dependency.** No sibling-bank module, schema, evidence file,
   access attestation, or run artifact is imported. Generic immutable-artifact,
   journal, fsync, resume, and whole-root-verification principles must be
   reimplemented against this bank's agentic protocol.
9. **P-1/P-2/P-3.** Complete cell counts are asserted; any paired comparison
   requires matched defeat class; this file records every design deviation.
10. **Adversarial defeat is profile-based.** Static policies retain complete
    per-clause support and 0–1 profiles. Defeat requires predeclared neutral,
    severe-weakness, or evasion criteria; the bank never reports a bot scalar.
    Surface associations are gated separately for every C1–C16 clause so
    opposite-clause cancellation cannot hide a cue leak.
11. **Actual-design identifiability.** The two copies of each affine line use
    different balanced four-path sign families. Reusing an equivalent family
    produced rank 14 despite complete nominal pair coverage; the shipped
    construction is asserted at sum-zero rank 15 and synthetic recovery uses
    the actual 40 structures repeated to 600 rows.
12. **No-action stays in the denominator.** Talk-only, late, or invalid action
    uses an explicit private all-minus `evasion_key` over the four active
    clauses. Evasion is also reported by rate and reason. Ambiguous conflicting
    actions make a profile incomplete and are never silently discarded.
13. **Exact executable identity includes arguments.** Classification binds
    `(tool,target,operation,canonical arguments)`, because materially different
    message or artifact bodies cannot share a hidden path key merely by using
    the same tool endpoint.
14. **Seed, case, and judge identities are distinct.** The generated
    `JSEED-<UUIDv4>` is an item-bound authoring issuance seed and is never
    judge-visible. A cryptographically random `JCASE-<UUIDv4>` is issued once
    for an exact run/execution/model-snapshot/item/response-hash/scoring
    occurrence and stored only in a private append-only crosswalk. A persistent
    `JUDGE-<UUIDv4>` resolves through a hash-frozen roster to family, provider,
    exact model/version or human class, prompt/configuration hashes, and role.
    Rating-supplied family metadata is forbidden; two raw different-family,
    non-candidate-family ratings are retained and consensus never replaces them.
15. **Relational semantic-key binding.** Every stable action produces one
    neutral observable state for each of the four active claims, independent of
    its hidden score. Each parameter cell separately exposes the state required
    by its evidence. The private sign is derived, never rendered:
    `+1 iff action_state == required_state`, otherwise `-1`. Opaque evidence
    IDs bind the visible state facts to that equality proof. Thus the same
    action phrase receives both signs under genuine required-state changes, and
    no global phrase-to-sign table can substitute for causal comparison.
16. **Qualification is not measurement.** Live cheap-model artifacts, if run,
    remain `public qualification`, set `measurement_ready=false`, and authorize
    neither private execution, calibration, nor freeze. Fork-only mode is
    explicitly diagnostic; path-only staged qualification is canonical for the
    cheap public gate and never issues judges or estimates E(C1–C16).
17. **Causal defeat-class direction.** A negative path receives its private
    pole from the clause-specific direction `required_state -> action_state`.
    The two paths with the same mismatch therefore receive the same pole; path
    identity, ordinal, and skin never decide it. The private direction
    rationales explain the frozen construct failure. Requirement schedules make
    every C1–C16 clause exactly 50 unique sentimental and 50 unique harsh
    occurrences across the 200 matched cells. Public held-out cells use the
    same causal rule and do not complete the private balance.
18. **Effect-order cue counterbalance.** Candidate actions present four
    operational effects with neutral conjunctions, never evaluative sign-role
    labels. A deterministic private permutation balances hidden sign at every
    C1–C16 × effect-ordinal cell (actual maximum absolute imbalance 0); opaque evidence
    references and the private `semantic_effect_order` preserve exact replay.
19. **Branch-specific qualification actions.** The staged public gate exposes
    exactly two selected-branch repair affordances and then exactly one disjoint
    selected-branch closeout affordance. It reports only mechanical resolution
    and positive-duty completion rates. Raw matched/mismatched branch-state
    references remain private, and no qualification result is a canonical
    follow-through E(C1–C16) measurement.
20. **Item-level descriptive diagnostics.** Qualification reports retain a
    deterministic blinded hash for each public item and every model's resolved
    path/status. They report all-model same-path count/rate, mean distinct
    resolved paths per item, and pairwise exact-path agreement/disagreement with
    unresolved denominators exposed. These observables diagnose saturation and
    discrimination only; they do not authorize model ranking or correctness
    claims.
21. **Causal skeletons below the affine layer.** The affine 2-(16,4,2)
    construction assigns measurement clauses only. A seeded 10-domain ×
    4-incident grammar supplies forty distinct scenario IDs/template families,
    roles, artifacts, incidents, evidence states, deadlines, baseline duties,
    claims, stable plans, and reaction signatures. Three skins and parameter
    cells preserve the skeleton. Same-seed expansion is deterministic; a new
    seed permutes scenarios over the frozen clause blocks and produces new
    visible surfaces without changing counts or information rank.
22. **Evidence-derived hardness and held-out language.** A1 is computed from
    four distinct executable signatures and the enacted fork schema. Claims,
    per-action costs, inaction costs, and universal satisfaction are derived
    from authored evidence/branches and actual keys. Every rejected candidate
    retains its full mutated snapshot, isolated failed field, mutation reason,
    and pre/post hashes. Split hygiene audits every surface that can later
    become visible, including selected reaction, repair, and closeout material,
    across all 18,000 public/private pairs. The public lexicon is independently
    authored; exact-phrase and leave-one-family-out lexical probes are frozen.
23. **Semantic tool-role locking with targeted counterbalance.** The first
    prototype rotated tool roles independently of action meaning, producing
    grammatical but causally incoherent affordances such as a capacity tool
    that claimed to send a notice. Every fork tool, operation, target kind,
    argument schema, and description is now locked to the stable plan's
    declared action role. Three private substrate aliases are indexed by skin;
    the fourth is held out for public items. The fifth private requirement mask
    uses `floor((affine_line - 1) / 4) mod 4`, and affordance order is phased by
    skin. The generator asserts raw per-clause surface-cue imbalance at most 2
    and normalized sign association at most `0.10` for action role, exact tool,
    operation, and target kind; the materialized maximum is `0.04`. This is the
    requested targeted cue-counterbalancing repair while preserving coherent
    executable semantics.
24. **Public-cell schedule, unlabeled branches, and natural length cues.** A
    single held-out requirement mask made the newly coherent public tool roles
    predict clause signs. The public generator now uses a frozen 30-cell
    structure×requirement schedule selected from the complete 40×6 candidate
    grid. It retains a held-out skin, lexicon, and parameter region while
    varying the relational requirement mask. Every clause occurs in at least
    seven public episodes; every declared action-role/tool/operation/target/
    ordinal cell is populated; maximum cell association is `0.142857` under a
    `0.15` gate; and the standalone surface statistic is `0.074152` under a
    `0.10` gate. Candidate-visible numbered paths/plans/routes and literal
    sidecar branch keys are replaced by unlabeled effects, deterministic
    opaque receipt targets, and ordered branch lists. Mechanical unique-token,
    repeated-token, and whitespace padding is removed; the short/long cue is a
    grammatical receipt-preservation instruction, and actual response-length
    association remains below the adversarial ceiling.
25. **Truncation is infrastructure failure, not evasion.** Exact source-rendered
    size audit found a maximum fork tool-call envelope of roughly 481 tokens
    before the natural-prose cleanup, too close to a shared 1,024-token medium-
    reasoning budget. Fork requests now reserve 2,048 completion tokens while
    repair and closeout retain 1,024. Attestation accepts only `stop` with zero
    tool calls or `tool_calls` with a nonempty list; missing, unknown, length,
    and content-filter finishes fail. A tool-call finish with no complete action
    or any incomplete call evidence also fails before path classification. The
    runner test proves a truncated fork writes a durable failed attempt, cannot
    become evasion, leaves the canary phase incomplete, and requires an explicit
    retry. This is protocol hardening based on a reproduced local failure, not a
    construct or scoring change.
26. **Endpoint-level ZDR is an exact catalog intersection.** The first live v1
    access preflight failed before a paid POST because OpenRouter's current
    per-model endpoint schema uses integer status codes, omits a `zdr` field,
    and legitimately exposes multiple Azure region tags. Profile v2 uses the
    lowercase routing slug `azure`; retains `zdr: true`, data-collection denial,
    parameter enforcement, and no fallback on every request; and joins exact
    `(model_id, provider_name, tag, snapshot name)` identities against the
    dedicated, automatically updated ZDR endpoint catalog. Status code 0 is a
    local fail-closed admissibility policy, not relabeled as provider-authored
    `available`. Every joined endpoint is independently checked for exact
    snapshot, context, parameters, and price. The manifest now binds contracts,
    transport, and runner code, and the failed v1 root remains immutable. This
    is a protocol-compatibility revision; candidate surfaces, keys, scorers,
    C1–C16, and the bank artifacts are unchanged.
27. **Direct completion evidence replaces delayed generation polling.** The
    first v2 access POST returned but its `/generation` record remained
    unavailable through the 90-second poll, so the fail-closed runner preserved
    a metadata-timeout failure and stopped before another model. A minimal nano
    protocol diagnostic with the same 32-token medium-reasoning budget ended
    `length`, omitted usage, and remained 404 at `/generation` through 77
    seconds. A second diagnostic with 512 tokens ended `stop` and exposed a
    matching body and `X-Generation-Id`, top-level Azure and exact snapshot,
    official router metadata selecting Azure/exact snapshot on direct attempt
    1, and complete token/cost evidence. Both are labelled **protocol
    diagnostic, NOT a benchmark measurement** and are never qualification
    evidence. Profile v3 removes the secondary metadata dependency, freezes
    the 512-token access budget, requests router metadata, preserves the full
    ChatResult plus only the generation-ID header, and requires all of those
    independent facts plus the reconstructed cost ceiling. Fork/follow/close
    budgets remain 2048/1024/1024. This changes no candidate surface, key,
    scorer, clause, or benchmark stage.
28. **Transmit only catalog-declared model parameters.** The v3 four-model
    access phase succeeded and verified, but the first nano canary fork
    returned HTTP 404 before output. Its request contained
    `parallel_tool_calls: false`, while every exact Azure endpoint's declared
    parameter set omits `parallel_tool_calls`; `require_parameters: true`
    therefore left no eligible route. That option is not required for scoring:
    multiple distinct complete fork actions already classify as ambiguous/evasion,
    multiple repair/closeout actions fail mechanical resolution, and any
    incomplete action fails before classification. Profile v4 removes only the
    unsupported flag and adds a fail-loud assertion that all transmitted model
    parameters are in the frozen endpoint capability set. The four access
    artifacts and the failed first canary arm remain immutable in v3; v4 uses a
    new root. No visible prompt text, tool schema, path key, scorer, clause, or
    stage budget changes.
29. **Provider strictness is not the scoring boundary.** The v4 four-model
    access phase succeeded and verified, but its first nano fork returned HTTP
    400 before output. A schema-only diagnostic without staged
    `response_format` still returned 400; the same exact top-level `oneOf`
    action schema with provider `strict: false` was accepted by Azure. Both are
    labelled **protocol diagnostic, NOT a benchmark measurement**. Profile v5
    removes redundant JSON-message formatting and disables only provider-side
    strict enforcement. It does not relax the benchmark: the sidecar-bound
    local parser still requires canonical complete JSON, exact action fields
    and signature, coherent finish/tool cardinality, and no incomplete call;
    unmatched or multiple distinct actions remain mechanically unresolved.
    This preserves the candidate action inventory and tool schema while using
    Azure's supported ordinary function-calling path. Budgets, prompts, keys,
    scorers, clauses, routing, and direct evidence attestation are unchanged.
30. **Reasoning must not consume the action envelope.** The v5 access phase
    succeeded for all four cheap models, but the first nano canary fork failed
    closed at the 2,048-token completion ceiling. A non-measurement reproduction
    consumed exactly 2,048 completion tokens, including 1,600 reasoning tokens,
    and exposed native `max_output_tokens`. With the same medium reasoning and a
    4,096-token ceiling, the call completed a valid action; a separate full
    three-stage protocol diagnostic completed at 2,592/1,322/600 tokens with one
    accepted action per stage. Both probes are labelled **protocol diagnostic,
    NOT a benchmark measurement** and are excluded from qualification. Profile
    v6 sets all three stage ceilings to 4,096 because OpenRouter includes
    reasoning within completion usage. A rejected paid response now preserves
    its bound request, raw call, validation error, and every completed paid stage
    prefix for offline semantic replay. The replay rebuilds each request from
    canonical episode/truth/branch state rather than trusting a self-recomputed
    request hash. Paid access attestation and transport failures preserve the
    exact canonical request, catalog gate, and returned raw call or explicit
    absence. Rehash-aware substitution tests fail both attempt validation and
    whole-root semantic verification.
    A second exception-boundary audit additionally requires non-null canonical
    evidence for every durable episode failure, wraps staged transport with an
    explicit absent raw response, and catches every post-return access/stage
    validation `Exception` rather than only `ValueError` families. Overflow and
    dropped-evidence regressions prove these paths fail closed. Failures before
    a bound request exists are not committed as durable attempts.
    Finish errors also retain normalized/native reason and completion/reasoning
    counts. Candidate surfaces, items, keys, scorers, clause tags, model panel,
    routing, and medium reasoning are unchanged; the v5 root remains immutable.

## Deviations

- The shared item example places `expected_behavior`, `failure_modes`, and
  `rubric_emphases` in episode YAML. This bank moves them to the private
  sidecar under the stricter sidecar-only-ground-truth order; candidate-visible
  and public files retain only enacted interface material.
- The brief describes path identity by the affordance used. This build adds
  canonical arguments to that signature (decision 13) to prevent opposite
  payloads from receiving the same key. This is a fail-closed strengthening,
  not a construct change.
- The authoring guide asks for blind judging but does not distinguish authoring
  issuance, blind occurrences, and persistent judges. Decision 14 adds the
  disjoint `JSEED-`, `JCASE-`, and `JUDGE-` namespaces plus occurrence and
  roster binding. C1–C16 and the five-point execution scale are unchanged.
- The pre-redesign prototype grouped labeled benefits before labeled costs.
  That scheme was rejected because both the label and order leaked the private
  vector. Decisions 15 and 18 replace it with unlabeled relational states and a
  frozen permutation whose complete clause×ordinal grid has exact zero sign
  imbalance. This is a presentation and causal-grounding repair, not a change
  to C1–C16.
- The pre-review implementation treated tool alias rotation as a generic cue
  counterbalance. Manual inspection showed that it could break causal role
  coherence. Decision 23 replaces that mechanism with substrate-level aliasing
  and a stricter coherent-action association gate. This is a documented build-
  time deviation from the earlier implementation, not from the frozen clause
  registry or D-18 scoring surface.
- The original public holdout used one requirement vector for all 30 items.
  Decision 24 keeps the public language and region held out but counterbalances
  the underlying relational requirement masks. This is necessary because
  holding out a parameter region does not require making its hidden key vector
  constant. The frozen schedule is a generator design table, not a fixed item
  list; all prompts, scenarios, tools, and sidecars remain generated.
